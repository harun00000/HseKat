# HseKat

Консольное приложение для учёта парка «ВышКат».

## Запуск

```bash
dotnet build
dotnet run --project HseKat
```

Для запуска тестов:

```bash
dotnet test
```

### После запуска доступны командыыыы:

- `1` — добавить транспорт;
- `2` — добавить вещь;
- `3` — показать количество объектов;
- `4` — показать суммарное энергопотребление;
- `5` — показать транспорт для новичков;
- `6` — показать весь инвентарь;
- `0` — выйти из программы.

### Доступный транспорт:

- `Bicycle`;
- `Scooter`;
- `ElectricBike`ю

### Доступные вещи:
- `Helmet`;
- `ChargingStation`.

Транспорт перед добавлением проходит проверку через `ServiceCenter`.

## Архитектурные решения

### Наиболее явно применённый принцип SOLID

Dependency Inversion Principle

Он применяется в `ParkService` (`Services/ParkService.cs`). Вместо зависимости от конкретного `ServiceCenter` класс зависит от интерфейса `IServiceCenter`:

```csharp
private readonly IServiceCenter _serviceCenter;

public ParkService(IServiceCenter serviceCenter)
{
    _serviceCenter = serviceCenter;
}
```

Конкретная реализация задаётся в `Program.cs`:

```csharp
services.AddSingleton<IServiceCenter, ServiceCenter>();
```

`ParkService` не создаёт `ServiceCenter` самостоятельно. В обычной программе ему передаётся `ServiceCenter`, а в тестах вместо него можно передать `ServiceCenterStub`.

### Сознательно ограниченный принцип SOLID 

Open/Closed Principle

`ParkService` работает с общим типом `Transport`, поэтому при появлении нового транспорта его менять не нужно.

А вот уже в `ConsoleApp.AddTransport()` конкретные виды транспорта перечислены вручную через if-else. Поэтому при добавлении нового вида транспорта нужно будет править вручную.

Для нашего небольшого проекта это разумно, было бы усложнением создавать отдельную фабрику только ради нескольких видов транспорта.

### Расширение проекта

Если добавить новый вид транспорта, например `Segway`, нужно создать класс `Segway : Transport` и добавить его в меню `ConsoleApp`. `ParkService` при этом менять не нужно.

Если добавить сотрудников, их логинее будет хранить отдельно от парковых штук, потому что сотрудники по условию не находятся на балансе. Существующие `Transport` и `Thing` менять не нужно.

Если добавить склад запчастей, его тоже можно реализовать отдельно. Учёт транспорта и вещей продолжит работать как раньше.

### Тестирование техосмотра и правила для новичков

Тесты находятся в проекте `HseKat.Tests`.

- `AddGoodTransport` проверяет успешное добавление транспорта.
- `DontAddBadTransport` проверяет отказ техосмотра.
- `GetBeginnerTransport` проверяет выбор транспорта для новичков.
- `EaseSixWorks` проверяет границу правила: `EaseOfUse >= 6`.

Для подмены техосмотра используется `ServiceCenterStub`, который реализует тот же интерфейс `IServiceCenter`.

```csharp
new ServiceCenterStub(true)
```

всегда разрешает добавление транспорта, а

```csharp
new ServiceCenterStub(false)
```

всегда запрещает его.

Так можно отдельно проверить работу `ParkService` фейковым тестом, а не настоящим `ServiceCenter`.

### Использование ИИ

ИИ использовался при написании unit-тестов, а также как инструмент поиска информации, фактически как браузер.
